<objective>
Brancher dans la gate les frontières d'architecture (dependency-cruiser), le code mort et les dépendances non déclarées (knip), et la duplication nouvelle (jscpd), per QUAL-03. Les règles sont écrites pour la disposition de `quality/layout.json` (défaut A de Q5) et pour le code réel du dépôt (canari, `src/db`, scripts de gate, tests).

Purpose: les agents prennent le raccourci d'importer ce qui est à portée, laissent du code orphelin et copient-collent. La règle « un outil MCP n'importe jamais la base » matérialise l'autorisation par construction des phases suivantes.
Output: `.dependency-cruiser.cjs`, `knip.json`, `.jscpd.json`, checks `arch`, `deadcode`, `duplication`.
</objective>

## Phase Goal

**As a** développeur du projet, **I want to** voir chaque PR jugée par une seule gate déterministe (`pnpm quality`), identique en local et en CI, qui bloque typage laxiste, violations d'architecture, failles de sécurité, tests faibles et contournements, **so that** aucune ligne de domaine écrite par un agent n'entre dans le dépôt sans avoir passé cette gate.
